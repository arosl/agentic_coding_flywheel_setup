Related: [index](../index.md), `AGENTS.md` ("Scope", "Upstream sync")

A redirect follows a symlink, so as root a dangling `~/.profile` pointing at `/etc/profile.d/x.sh` would have root create that file, and a link to `/etc/bash.bashrc` would have root append to it; a link swapped in mid-run did the same, which a check before the write can't stop. As the user, a link reaches only what the user could write: a dotfiles repo's file is written through, and a root file is left alone, with a warning that gives the line to add. Ubuntu moves a linked `~/.zshrc` aside as its `.pre-acfs` backup (the link itself), so the file it points at keeps its content, and then writes the loader. A regular dotfile root left behind goes to the user first (`chown -h`), where upstream chowns it after. The generated `shell.omz` path already writes these files as the target user. `tests/unit/test_install_chown_no_follow.bats` runs `setup_shell` with a home only `run_as_target` may write, and covers each dotfile.
